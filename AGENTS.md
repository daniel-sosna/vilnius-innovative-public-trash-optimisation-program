# Agent Instructions

This project uses Spec-Driven Development with [OpenSpec](https://github.com/Fission-AI/OpenSpec).

## Project governance

`openspec/config.yaml` is the single source of truth for the project's context, decision priorities, engineering principles and per-artifact rules. Read it before starting any task, including work done outside the OpenSpec workflow, and follow it. Do not duplicate its contents elsewhere; update that file instead.

## Workflow

Feature work goes through OpenSpec changes:

1. **Explore** (optional): `/opsx:explore` to clarify requirements or investigate uncertainty.
2. **Propose**: `/opsx:propose <feature>` creates the proposal, specs, design and tasks under `openspec/changes/<name>/`.
3. **Apply**: `/opsx:apply` implements the tasks.
4. **Archive**: `/opsx:archive` merges the accepted specs into `openspec/specs/`.

The workflow skills are provided per agent in `.claude/`, `.agents/` (Codex) and `.github/` (GitHub Copilot). They are generated by `openspec init`/`openspec update`; do not edit them by hand.

## Development data

Never run `bin_sync` to get development data: parsing the VASA API is too slow. Load collection data from CSV exports with `python -m app.interfaces.table_import` (see the README section "Import table CSV exports"). Before any task that needs collection data, check that `backend/data/` contains `sites_<digits>.csv`, `bins_<digits>.csv` and `bin_hist_<digits>.csv`. If any is missing, stop and ask the developer to add the exports.

See `README.md` for the project structure and how to run it locally.
